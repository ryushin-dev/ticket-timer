`http://localhost:8787`で暗号化前の画面を確認できます。公式受付一覧から受付・公演日・席種を選び、取得日時・移動までの秒数・再取得設定を編集します。取得日はカレンダー、時刻はPCの時刻入力またはスマホのスクロール選択、ミリ秒は数字入力で指定します。±100ms・±1秒・±1分、「今日」「14:00」「1分後」のショートカットも使えます。時刻の微調整は秒・分・日付をまたいで繰上がり・繰下がりします。

移動日時は **取得予定日時＋指定秒数** で自動計算します。初期値は3秒で、0秒や3.500秒などミリ秒単位に変更できます（0〜86400秒）。取得日時または秒数を変えると表示と実行設定が更新されます。実際の取得完了時刻から3秒待つという意味ではありません。HTML取得が移動予定を過ぎた場合は取得・席選択完了後すぐ移動します。日本時間として解釈し、従来の保存した取得日時も新しい入力欄に引き継ぎます。旧形式の移動日時は、新しく指定した秒数からの計算に置き換えます。

「今すぐ一覧を確認」は移動しません。「予約開始」では、取得が完了したらすぐ全席のURLを表示し、選択した席だけを指定した移動日時に同じタブで開きます。待機中も一覧を確認できます。各候補のURLを手動でクリックした場合は別タブで開き、自動移動の対象は変わりません。

「今すぐ取得して移動」は指定日時を使わず、HTMLを取得して希望の公演日・席種を一意に選択できたらすぐ同じタブで移動します。取得失敗・候補なし・複数一致の場合は停止します。購入・決済は手動です。

設定は端末のlocalStorageに平文で保存します。「公式ページの受付一覧を取得」ボタンから受付を選んでください。保存済みの受付が一覧にあれば復元し、公演日・席種もその受付に含まれる場合だけ復元します。別受付への自動切替はしません。実行前に取得日時が未来の日本時間になっていることを確認してください。

「公式ページの受付一覧を取得」で、見出しに「先着」と書かれた受付だけを表示します。受付タイトルの手入力は不要です。選んだ受付内の「対象公演」「対象席種」から公演日・席種の選択肢を作り、対象外のものは選択できません。顔写真登録などの注意書きは席種に含めません。前の選択が対象外になった場合は未選択に戻します。申込リンクが未公開でも、対象公演・席種が書かれていれば事前設定できます。

受付一覧を取得した時と受付を選び直した時に、「受付期間」の開始日時＋100msをHTML取得日時に設定します。移動日時はそこから指定秒数後です。読み取れない場合や、公演別に複数の開始日時がある場合は手動で設定してください。年がない日付はツアーページの説明の年、説明にも年がなければ端末の日本時間の年を使います。終了済みの受付も記載された開始日時を設定しますが、過去の日時では予約実行できません。

自動設定後も手動調整でき、「販売開始＋0.1秒を再設定」で戻せます。予約時の再取得では手動調整した時刻を上書きしません。スマホでは時・分・秒を上下にスクロールして選択し、PCでは時刻入力欄で編集します。ミリ秒入力と±100ms・±1秒・±1分のボタンは両方で使えます。

## パスワード付き公開ファイルを作る

```sh
npm run build
```

ターミナルでパスワードを2回入力します。入力内容は画面に表示せず、コマンド引数・環境変数・ファイルにも保存しません。12文字以上が必要です。長いパスフレーズを使ってください。入力後、`dist/index.html`と`dist/.nojekyll`を生成します。

公開ファイルには、解除画面と暗号化されたHTML・JSだけを含めます。PBKDF2-HMAC-SHA256（600,000回、ランダムな16バイトsalt）でAES-256-GCM鍵を生成し、12バイトのランダムIVで暗号化します。鍵・パスワード・照合用ハッシュは公開しません。ブラウザのWeb Cryptoで解除し、パスワードは送信・保存しません。再読込すると再度パスワードが必要です。

これは暗号化による静的コンテンツ保護です。サーバー側のアカウント認証や試行回数制限ではありません。解除に成功した利用者は中身をコピーできます。公開済みの旧ファイルはパスワード変更後も旧パスワードで復号できるため、変更で回収・失効はできません。設定のlocalStorageは暗号化対象ではないので、個人情報やカード情報は入力しない構成です。

暗号化版のプレビュー:

```sh
npm run serve
```

`http://localhost:8787`でビルド時のパスワードを入力します。HTTPSまたはlocalhostが必要です。file://での直接オープンは使いません。

## GitHub Pagesへ置く

公開設定は`publish.config.json`に記録しています。再公開やパスワード変更は`npm run build`でビルドし直し、`npm run verify-public`で確認してから、公開用リポジトリの2ファイルを更新してください。GitHubの「Add file → Upload files」で`dist`の2ファイルをルートへアップロードし、`main`にコミットすると再デプロイされます。`.nojekyll`が見えない場合はmacOSのファイル選択でCommand＋Shift＋ピリオドを押します。

1. この開発フォルダとは別に、公開用リポジトリを作ります。
2. **distの中身だけ**（index.htmlと.nojekyll）をリポジトリのルートに置きます。src、scripts、tests、このREADMEや既存ticketフォルダのHARなどは公開しません。
3. GitHubのリポジトリSettings → Pages → Deploy from a branchで公開用ブランチ・`/ (root)`を選びます。
4. HTTPSの公開URLで、正しいパスワード・誤ったパスワードと「今すぐ一覧を確認」を検証します。

開発フォルダをそのまま公開リポジトリにコミットしないでください。`.gitignore`はdistの誤コミットを防ぐために付けていますが、srcの公開を暗号化してくれるものではありません。公開ファイルの生成はローカルで行います。

## 実行順と制限

「SHADOWS」と「ゼンジン未到2026」の公式受付一覧に対応しています。「公式ツアーページ」を`https://mrsgreenapple.com/feature/zenjinmito_2026_ticket`に変更して、受付一覧を取得してください。2026/10/14の公式HTMLで、先着3受付（7月・5月のFC直前追加販売、4月の直前販売）、公演日・エリア名・開始日時の抽出を確認しました。スタンドエリア・パノラマエリアなどもその受付の記載から取得します。

受付の見出し`h3.slide-toggle`、申込リンク`a.common-btn`、項目見出し`h4`を手がかりにしています。公演名・tour番号を固定した処理ではありませんが、同じサイトでもHTML構造が違うページは追加対応が必要です。公式受付ページでは購入リンクを解析し、チケットぴあの申込リンクでは外部HTMLを取得せず申込サイトへの移動まで行います。チケットぴあの公演日・席種は遷移後に手動選択してください。抽選受付は一覧に含めません。

取得日時 → ツアーページGET → 正規化した受付タイトルでボタンのhrefを特定 → 公式受付ページGET → 月日・席名で完全一致の購入URLを選択 → 移動日時以降に同じタブで移動します。

HTML取得が遅ければ移動日時を過ぎても取得・選択完了まで待ちます。公開前のhrefが空の場合だけ設定回数で再取得します。通信は直列で、解除するとタイマーと取得も中止します。別受付・別席へは切り替えません。確認ボタンはクリックせず、以前のCLI版と同じくHTML中の席リンクを読みます。ログイン・購入・決済は手動です。

ブラウザのCORSを使い、Cookieと独自ヘッダーを送らず取得します。確認した公式ページは外部取得を許可していますが、実際に利用する受付の設定変更などで取得できなくなる場合があります。CORSを無視する実装や代理サーバーはありません。

ページを閉じたりスマホをロックしたりすると予約は動かないことがあります。バックグラウンドではタイマーが遅れるため、待機ページを前面にしてください。JSTでミリ秒を設定できますが時計は端末依存で、サーバーへの到着時刻を保証しません。
